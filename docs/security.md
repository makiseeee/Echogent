# 网络拓扑与安全规范

本文档详述 **Echogent (Echo 7.0)** 的端侧网络拓扑、监听端口、接口权限边界与敏感数据防护准则。

## 2. 接口与执行安全边界

### 2.1 零远程代码执行 (Zero RCE)
- 彻底摒弃了早期可能存在安全风险的远程通用代码执行通道；
- 电脑端 `echo_pc_agent` 仅作为**只读状态探针**，不接收任何 Shell、命令行参数或外部调用请求；
- 数学计算器严格运行在沙盒化 AST 解释器内 (`safe_calculator.py`)，白名单限定仅允许 `Add`, `Sub`, `Mult`, `Div`, `Pow`, `Mod` 及基本数学函数（如 `sqrt`, `sin`, `cos` 等），任何尝试调用 `__import__`、系统内置函数或属性访问的 AST 节点均会被静态拦截抛出安全异常。

### 2.2 知识库与文件边界
- **有界读取限制**：对 Obsidian 笔记的读取强制限制在 4,000 字符以内；超长笔记通过滑动窗口算法仅提取关键词上下文，彻底阻断利用巨型笔记实施上下文占位攻击的风险；
- **两阶段写入防线**：任何文件创建与链接改动必须由 LLM 发起 `obsidian_prepare_create`，将路径与完整正文显式呈现给 wenbo，仅在下一轮对话获得明确肯定授权后方可由 `obsidian_commit_create` 写入。

## 3. 凭据与私密数据防泄漏规范

1. **版本控制绝密隔离**：
   - 项目根目录下的 `.env`、`mcp-executor/.env`、`data_v4.db`、`*.db` 数据库及包含 QQ 号、密码和个人日程的 `MEMORY.md`、`USER.md`、`RELATIONSHIP.md` 必须受 `.gitignore` 保护，严禁推送到公开仓库；
   - 包含个人电话、学籍等真实身份信息的档案严禁作为上下文全量注入公网大模型，仅由本地规则过滤后提取最小必要事实。
2. **防火墙与网络隔离**：
   - 手机端所有敏感管理端口（`6185`, `6099`, `8022`）默认不直接对公网暴露；
   - PC Windows 防火墙策略针对 `8765` 端口仅允许来自回环及已授权的手机 IP 访问。
