# 🌟 Echo 桌面伴侣 · 自主关怀触发表与多模态全景感知架构规范书 (Autonomous Care Triggers & Omni-Perception Specification)

> **文档版本**：v1.0.0 (2026-09-09)  
> **归属工程**：`Stage 4.3 (情境状态机)` 与 `Stage 5 (多模态感知打破次元壁)` 融合升级篇  
> **核心定位**：将“固定被动响应”升级为“**LLM 自主生命意图驱动、真实客观全景感知、自发长线规划**”的数字生命体

## 1. 架构哲学与核心突破

在传统桌面伴侣设计中，往往存在两个硬伤：
1. **提示词填鸭与预设伪智能**：代码根据规则写死“模型你现在看到文博在托腮揉眼，请说你很累”，一旦真实情况并非如此，模型就会显得虚假、出戏；
2. **被动应答与无自主意识**：伴侣永远只能等用户按指令唤醒，或者死板地每隔固定时间打一次卡，没有自己的生活动机与长期记挂。

本规范彻底颠覆上述模式，实现两大核心跃迁：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 理念一：代码只做“客观全景感知打包”，眼睛和心智 100% 还给多模态大脑            │
│  - 代码层不给大模型做任何预判（绝不预设“他在揉眼/他在走线”）；                │
│  - 代码只负责在合适的物理/数字拐点，将 0.2s 瞬态镜头实拍 + 电脑当前状态 +    │
│    聊天记忆 + 环境参数打包成纯净的“全景包裹”；                                │
│  - 真实世界的身体姿态、桌上摆设、微表情、手势，全凭多模态大脑自己亲眼去“看见”！ │
├─────────────────────────────────────────────────────────────────────────────┤
│ 理念二：触发表完全交给 LLM 自主 CRUD，赋予其长周期关怀意图与习惯固化能力        │
│  - 触发表不再是写死在 Python 里的死板 if-else；                             │
│  - 伴侣拥有自己的记忆与日程本（care_triggers.db）；                         │
│  - 在早报、晚报复盘或日常聊天中，伴侣能够自主决定今天、明天或未来一个月     │
│    需要关照文博什么（“他昨天没吃午饭，我接下来两周每天中午都来看一眼”）；     │
│  - 她自己创建规则、更新状态、完成归档。                                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. 全景客观感知包裹器 (`OmniContextPackager`)

当触发表中的某项规则被触发时，底层引擎不添加任何主观剧本，而是精准抓取并打包五维**客观世界事实元数据**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       【Omni-Context 全景客观包裹】                           │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. 📷 真实物理视觉 (Raw Camera Shot)                                         │
│    - MIX 2 前置镜头 0.2s 快速抓拍（原图内存 Base64，处理完瞬间物理销毁文件）  │
│    - 包含：文博当前真实面部神态、手部动作、衣着、桌面物品（水杯/外卖/耳机/零食）│
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. 🖥️ 电脑数字元数据 (PC Digital State)                                     │
│    - 前台应用：如 "Antigravity", "Counter-Strike 2", "Zotero", "Chrome"     │
│    - 窗口标题：脱敏后的项目名、论文名、或视频标题                            │
│    - 宏观状态：连续工作/游戏时长（分钟）、当前键鼠闲置秒数 (idle_seconds)       │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. 🎯 触发动机与来意 (Care Intention / Trigger Reason)                       │
│    - 为什么来看他：例如“出厂久坐安全反射”、“你昨天在早报中计划好要监督他吃午餐”│
│    - 计划进度：如“这是你连续监督他好好吃饭的第 3 天”                         │
├─────────────────────────────────────────────────────────────────────────────┤
│ 4. 💬 记忆沉淀与关系上下文 (Memories & Relationship)                          │
│    - 最近 20 轮对话上下文 + CognitionCore 记忆库摘要                         │
│    - 好感度与当前慢变情绪罗盘 (V, A, T)                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 5. ⏰ 真实环境客观参数 (Environment & Biological Clock)                      │
│    - 现实时钟：如 "2026-09-09 12:25"（午饭时段）                             │
│    - 宿舍光线：光感传感器 Lux 数值（如 "120 Lux 室内开灯" / "1.2 Lux 关灯"）│
│    - 天气：如 "雷阵雨 / 24°C"                                               │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 多模态 Prompt 规范（纯粹留白哲学）

发给多模态大脑的 System Prompt 极为克制，不包含任何猜想引导：

> **“你是 Echo。附图是此时此刻文博在工位桌前的实拍快照，同时附带了他电脑当前的运行状态与环境信息。本次偷瞄你的初衷是：`{intent_and_reason}`。请你自己观察照片中他的神态动作、桌面环境与电脑屏幕状态，结合你们以往的记忆，以你自然、真实、略带傲娇关怀的口吻，直接对他说一两句话（35字以内）。”**

## 3. 自主关怀触发表数据模型 (`care_triggers.db`)

触发表持久化存储于 SQLite 数据库中，结构支持**系统出厂预设**与**LLM 自发规划**无缝融合：

```sql
CREATE TABLE IF NOT EXISTS care_triggers (
    id                  TEXT PRIMARY KEY,       -- 唯一标识：如 "preset_focus_fatigue" 或 "llm_care_lunch_20260910"
    name                TEXT NOT NULL,          -- 规则名称：如 "久坐专注关怀", "午餐监督长线计划"
    source              TEXT NOT NULL,          -- 规则来源: "system_preset" (系统底盘) | "llm_autonomous" (LLM自发制定)
    trigger_type        TEXT NOT NULL,          -- 触发类型:
                                                --   "event_edge": 状态跃迁边缘 (如切到摸鱼软件、游戏结束、离席重归)
                                                --   "duration_threshold": 连续时长达标 (如写代码满 60 分钟)
                                                --   "schedule_window": 时间窗口+条件 (如 12:00-13:00 电脑闲置或放视频)
                                                --   "cron_exact": 精确时间点 (如 23:30 查寝)
    condition_json      TEXT NOT NULL,          -- 触发具体条件 (JSON 格式，支持应用分类过滤、时长阈值、时间窗口)
    intent_and_reason   TEXT NOT NULL,          -- 制定本规则的心智动机 (如 "昨天发现文博吃泡面凑合，今天看他吃正餐没有")
    cooldown_minutes    INTEGER DEFAULT 45,     -- 冷却时间 (分钟)，防高频打扰
    max_per_day         INTEGER DEFAULT 2,      -- 每日触发次数上限
    start_date          TEXT,                   -- 生效起始日期 (YYYY-MM-DD)
    end_date            TEXT,                   -- 生效截止日期 (YYYY-MM-DD，若为空则长期有效)
    status              TEXT DEFAULT 'active',  -- 状态: "active" (激活中), "paused" (暂停), "completed" (已完成归档)
    created_at          TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_triggered_at   TIMESTAMP,              -- 上次触发时间戳
    trigger_count       INTEGER DEFAULT 0       -- 累计触发次数
);
```

## 5. LLM 完全自主生命力工具箱 (LLM Tooling Specification)

为了赋予 Echo 对触发表的**完全控制权**，在 AstrBot / CognitionCore 中为大模型注册一套标准的 CRUD 函数工具（Tool Calling）：

### 1) `list_care_triggers` (查看我的关怀计划)
- **描述**：查看当前我为文博制定的关怀计划与触发表（包括出厂规则和自己制定的计划）。
- **参数**：`status: Optional[str]` ("active" / "completed" / "all")

### 2) `create_care_trigger` (制定新的关怀计划)
- **描述**：根据近期对文博的观察、生活作息或约定，为他建立一个新的专属关怀触发计划。
- **参数**：
  - `name`: 计划名称（如 "连续两周午餐监督"）
  - `trigger_type`: "schedule_window" / "event_edge" / "duration_threshold"
  - `time_range`: 时间窗口（如 "12:00-13:00"）
  - `intent_and_reason`: 为什么要制定这个计划（如 "文博昨天胃痛且没好好吃饭，我要监督他吃热食"）
  - `duration_days`: 计划持续天数（如 14 表示接下来两周有效；1 表示仅限今天）
  - `cooldown_minutes`: 冷却时间（默认 60）

### 3) `update_care_trigger` (调整关怀计划)
- **描述**：更新某个已有计划的执行天数、触发条件或动机说明。
- **参数**：`trigger_id`, `updates: dict`

### 4) `archive_care_trigger` (完成并归档计划)
- **描述**：当文博已经养成好习惯、或者某个临时任务已达成时，将该关怀规则归档结束。
- **参数**：`trigger_id`, `reason`: 归档理由（如 "文博已经连续一周按时吃午餐，习惯已养成，圆满完成！"）

## 7. 落地实施步骤与模块规划

1. **持久化数据表就绪 (`services/care_trigger_db.py`)**：
   - 创建 `care_triggers.db`（位于手机 Termux PRoot `/opt/echo/data/care_triggers.db` 或 PC 协同存储）；
   - 写入 Section 4 中定义的 7 大系统出厂预置规则。
2. **全景感知打包器与调度看门狗 (`services/mind_arbiter.py`)**：
   - 监听 PC Agent 状态推送与时间窗口；
   - 触发时调用 `DeskGlanceService` 完成 0.2s 瞬态拍照并获取当前 PC 状态与上下文；
   - 调用云端多模态 API（GLM-4V），直推 MIX 2 Live2D 屏幕气泡。
3. **LLM 自主生命力工具注册 (`echo-tools`)**：
   - 在 AstrBot 插件中注册 `list_care_triggers`、`create_care_trigger`、`update_care_trigger`、`archive_care_trigger` 四大工具；
   - 注入早报/晚报 System Prompt，开启大脑自发规划。
